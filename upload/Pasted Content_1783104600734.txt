━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Create the following PostgreSQL schema in Supabase. Every table must have
RLS enabled. Write all SQL as a single migration file.

─────────────────────────────
TABLE 1: profiles
─────────────────────────────
Extends Supabase auth.users. Created automatically via trigger on signup.

  id                  UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE
  full_name           TEXT NOT NULL
  email               TEXT NOT NULL UNIQUE
  avatar_url          TEXT
  phone               TEXT
  is_onboarded        BOOLEAN DEFAULT FALSE
  created_at          TIMESTAMPTZ DEFAULT NOW()
  updated_at          TIMESTAMPTZ DEFAULT NOW()

Trigger: after INSERT on auth.users → auto-create profiles row.

─────────────────────────────
TABLE 2: organizations
─────────────────────────────
Top-level tenant. A holding umbrella. No employees live here.

  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid()
  name                TEXT NOT NULL
  slug                TEXT NOT NULL UNIQUE
  logo_url            TEXT
  owner_id            UUID NOT NULL REFERENCES profiles(id)
  subscription_plan   TEXT NOT NULL DEFAULT 'free'
                      CHECK (subscription_plan IN ('free','starter','growth','enterprise'))
  subscription_status TEXT NOT NULL DEFAULT 'active'
                      CHECK (subscription_status IN ('active','past_due','cancelled','trialing'))
  is_active           BOOLEAN DEFAULT TRUE
  metadata            JSONB DEFAULT '{}'
  created_at          TIMESTAMPTZ DEFAULT NOW()
  updated_at          TIMESTAMPTZ DEFAULT NOW()

─────────────────────────────
TABLE 3: companies
─────────────────────────────
Legal operating entity under an Organization. All business data lives here.

  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid()
  organization_id     UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE
  name                TEXT NOT NULL
  legal_name          TEXT
  slug                TEXT NOT NULL UNIQUE
  logo_url            TEXT
  base_currency       TEXT NOT NULL DEFAULT 'PKR'
  country_code        TEXT NOT NULL DEFAULT 'PK'
  tax_id              TEXT          -- NTN or STRN for Pakistan
  tax_id_type         TEXT          -- 'NTN' | 'STRN'
  address             JSONB         -- { street, city, province, postal_code, country }
  phone               TEXT
  email               TEXT
  website             TEXT
  timezone            TEXT NOT NULL DEFAULT 'Asia/Karachi'
  fiscal_year_start   INT  NOT NULL DEFAULT 1   -- month number
  is_active           BOOLEAN DEFAULT TRUE
  metadata            JSONB DEFAULT '{}'
  created_by          UUID NOT NULL REFERENCES profiles(id)
  created_at          TIMESTAMPTZ DEFAULT NOW()
  updated_at          TIMESTAMPTZ DEFAULT NOW()

─────────────────────────────
TABLE 4: roles
─────────────────────────────
Fully custom, company-scoped roles. No hardcoded role names in code.

  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid()
  company_id          UUID NOT NULL REFERENCES companies(id) ON DELETE CASCADE
  name                TEXT NOT NULL               -- e.g. "Warehouse Manager"
  description         TEXT
  role_tier           TEXT NOT NULL DEFAULT 'standard'
                      CHECK (role_tier IN ('elevated','standard'))
  -- elevated = Owner, Founder, Co-Founder, Investor (bypass all permission checks)
  -- standard = regular custom roles
  is_system_role      BOOLEAN DEFAULT FALSE
  -- system roles: owner, founder, co_founder, investor — cannot be deleted
  system_role_key     TEXT UNIQUE
  -- 'owner' | 'founder' | 'co_founder' | 'investor' | NULL
  is_active           BOOLEAN DEFAULT TRUE
  created_by          UUID REFERENCES profiles(id)
  created_at          TIMESTAMPTZ DEFAULT NOW()
  updated_at          TIMESTAMPTZ DEFAULT NOW()

  UNIQUE(company_id, name)

─────────────────────────────
TABLE 5: role_permissions
─────────────────────────────
Permission keys attached to standard roles. Elevated roles bypass this entirely.

  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid()
  role_id             UUID NOT NULL REFERENCES roles(id) ON DELETE CASCADE
  company_id          UUID NOT NULL REFERENCES companies(id) ON DELETE CASCADE
  permission_key      TEXT NOT NULL
  -- dot-notation format: "module.action"
  -- Examples:
  --   inventory.view, inventory.adjust, inventory.create
  --   orders.view, orders.create, orders.fulfill, orders.cancel
  --   employees.view, employees.invite, employees.terminate
  --   reports.view, reports.export
  --   settings.company.view, settings.company.edit
  --   integrations.view, integrations.manage
  --   kpi.view, kpi.manage
  created_at          TIMESTAMPTZ DEFAULT NOW()

  UNIQUE(role_id, permission_key)

TABLE 6: employees
─────────────────────────────

TABLE 7: invitations
─────────────────────────────
Token-based email invitations. Works whether user exists or not.

  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid()

PART 2: HELPER FUNCTIONS & TRIGGERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Create the following PostgreSQL functions:

1. get_active_company_id() RETURNS UUID
   Reads user_settings.active_company_id for the current auth.uid().
   Used in ALL RLS policies. Must be SECURITY DEFINER, STABLE.

2. get_active_org_id() RETURNS UUID
   Reads user_settings.active_org_id for the current auth.uid().

3. is_elevated_employee(p_company_id UUID) RETURNS BOOLEAN
   Checks if current user's employee record for p_company_id has a role
   with role_tier = 'elevated'. Used in admin-only RLS policies.

4. has_permission(p_company_id UUID, p_permission_key TEXT) RETURNS BOOLEAN
   Checks role_permissions for current user's role in p_company_id.
   If the user's role_tier = 'elevated', return TRUE immediately (bypass).
   Otherwise check role_permissions table.

5. handle_new_user() — TRIGGER FUNCTION
   After INSERT on auth.users:
   - Creates profiles row
   - Creates user_settings row
   - Marks is_onboarded = FALSE

6. update_updated_at() — TRIGGER FUNCTION
   Updates the updated_at column to NOW() before any UPDATE.
   Apply this trigger to: profiles, organizations, companies, employees,
   roles, user_settings.

PART 3: ROW LEVEL SECURITY (RLS) POLICIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Enable RLS on ALL tables. Write explicit policies for each.

profiles:
  SELECT: auth.uid() = id
  UPDATE: auth.uid() = id

organizations:
  SELECT: owner_id = auth.uid()
          OR EXISTS (SELECT 1 FROM employees e 
                     JOIN companies c ON c.id = e.company_id 
                     WHERE c.organization_id = organizations.id 
                     AND e.user_id = auth.uid() 
                     AND e.status = 'active')
  INSERT: auth.uid() IS NOT NULL (any logged in user can create an org)
  UPDATE: owner_id = auth.uid()
  DELETE: owner_id = auth.uid()

companies:
  SELECT: company_id = get_active_company_id()
          AND EXISTS (SELECT 1 FROM employees 
                      WHERE company_id = companies.id 
                      AND user_id = auth.uid() 
                      AND status = 'active')
  INSERT: organization owner can create companies
  UPDATE: is_elevated_employee(id) = TRUE
  DELETE: DISABLED (use is_active = FALSE instead)

employees:
  SELECT: company_id = get_active_company_id()
          AND company_id IN (SELECT company_id FROM employees 
                              WHERE user_id = auth.uid() 
                              AND status = 'active')
  INSERT: has_permission(company_id, 'employees.invite') = TRUE
  UPDATE: is_elevated_employee(company_id) = TRUE
          OR (auth.uid() = user_id AND -- employee can update own limited fields
              -- Only allow updating: avatar, phone on own profile)
  DELETE: DISABLED (use status = 'terminated' instead)

roles:
  SELECT: company_id = get_active_company_id()
  INSERT: has_permission(company_id, 'settings.roles.manage') = TRUE
  UPDATE: has_permission(company_id, 'settings.roles.manage') = TRUE
          AND is_system_role = FALSE
  DELETE: has_permission(company_id, 'settings.roles.manage') = TRUE
          AND is_system_role = FALSE

role_permissions:
  SELECT: company_id = get_active_company_id()
  INSERT: is_elevated_employee(company_id) = TRUE
  DELETE: is_elevated_employee(company_id) = TRUE

invitations:
  SELECT: invited_by = auth.uid()
          OR invited_email = (SELECT email FROM profiles WHERE id = auth.uid())
  INSERT: has_permission(company_id, 'employees.invite') = TRUE
  UPDATE: token IS NOT NULL (accepting via token — public but token-gated)

user_settings:
  SELECT: user_id = auth.uid()
  INSERT: user_id = auth.uid()
  UPDATE: user_id = auth.uid()

audit_logs:
  SELECT: company_id = get_active_company_id()
          AND is_elevated_employee(company_id) = TRUE
  INSERT: auth.uid() IS NOT NULL
  UPDATE: DISABLED (immutable — no updates ever)
  DELETE: DISABLED (immutable — no deletes ever)

metric_events:
  SELECT: company_id = get_active_company_id()
  INSERT: auth.uid() IS NOT NULL
  UPDATE: DISABLED
  DELETE: DISABLED

PART 5: AUTHENTICATION FLOWS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Implement all 6 flows using Supabase Auth + Next.js Server Actions:

─────────────────────────────
FLOW 1: REGISTRATION
─────────────────────────────
Form fields: full_name, email, password, confirm_password
Zod validation: min 8 chars password, email format, passwords match
Server Action:
  1. supabase.auth.signUp({ email, password, options: { data: { full_name } } })
  2. Supabase trigger auto-creates profiles + user_settings rows
  3. Return success → redirect to /onboarding
  4. Insert audit_log: action "auth.registered"

─────────────────────────────
FLOW 2: LOGIN
─────────────────────────────
Form fields: email, password
Server Action:
  1. supabase.auth.signInWithPassword({ email, password })
  2. Check if profiles.is_onboarded = TRUE
  3. Check if user has pending invitations for their email
  4. If is_onboarded = FALSE → redirect to /onboarding (pass pending invites)
  5. If is_onboarded = TRUE → check user_settings.active_company_id
  6. If active_company_id is NULL → redirect to /onboarding
  7. Else → redirect to /dashboard
  8. Insert audit_log: action "auth.login"

─────────────────────────────
FLOW 3: LOGOUT
─────────────────────────────
Server Action:
  1. supabase.auth.signOut()
  2. Clear Zustand workspace store
  3. Redirect to /login
  4. Insert audit_log before sign out: action "auth.logout"

─────────────────────────────
FLOW 4: FORGOT PASSWORD (OTP Code Flow)
─────────────────────────────
This is a 3-step flow:

STEP 1 — /forgot-password
  Form: email input
  Server Action:
    supabase.auth.resetPasswordForEmail(email, {
      redirectTo: process.env.NEXT_PUBLIC_APP_URL + '/reset-password'
    })

PART 11: CRITICAL RULES — DO NOT VIOLATE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. NEVER use "any" TypeScript type. Use generated Supabase types everywhere.

2. NEVER expose service_role key on client side. 
   Server Supabase client is only used in Server Actions and middleware.

3. NEVER write WHERE company_id = X filters in Next.js code.
   RLS handles all data isolation. Trust the database.

4. NEVER delete employees records. Set status = 'terminated' only.

5. NEVER delete audit_logs or metric_events rows. These are immutable.

6. NEVER hardcode permission strings in components.
   Always import from /lib/constants/permissions.ts

7. EVERY Server Action must:
   a. Validate input with Zod before any database operation
   b. Use the server Supabase client (never browser client)
   c. Return typed { success: boolean, data?: T, error?: string }
   d. Call insertAuditLog at the end on success

8. All company-scoped data tables that will be built in future modules 
   (orders, products, inventory, shipments, returns) MUST include:
   - company_id UUID NOT NULL
   - created_by_employee_id UUID REFERENCES employees(id)
   - created_at TIMESTAMPTZ DEFAULT NOW()
   - updated_at TIMESTAMPTZ DEFAULT NOW()
   This ensures KPI system can always track who did what.

9. Password reset must use the OTP/token flow via Supabase's 
   verifyOtp method — NOT a custom code system.

10. All forms must show proper loading states, disabled buttons during 
    submission, and error messages using Sonner toasts.
