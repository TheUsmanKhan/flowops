    28→The Inventory Core module is **architecturally sound at the ledger level** — `processInventoryTransaction()` in `src/lib/inventory.ts` is a genuine single write-point for `InventoryPool`, with WAC recalculation, immutable `InventoryTransaction` rows, and 1:1 `AvgCostHistory` coverage (verified: 44 history rows for 44 avgCost-changing txns, 0 orphans).     30→**However**, the module has **two critical runtime bugs** that are currently producing real-world data inconsistencies in the live database:
    31→

    33→2. **INV-002 (Critical)** — The `/api/inventory/receive-returned-stitched` route — claimed by PRODUCTS_AUDIT (PROD-002) as the "working equivalent" of the broken `/api/returned-stitched` route — does NOT actually create a `ReturnedStitchedInventory` row at all.     40→
    41→**Task:** Verify whether `POST /api/inventory/receive-returned-stitched` correctly creates BOTH a `ReturnedStitchedInventory` row AND an `InventoryTransaction` row with a valid `inventoryTxnId` link, for both `condition='damaged'` and `condition!='damaged'` paths.
    42→
    43→**Files read:**
    44→- `src/app/api/inventory/receive-returned-stitched/route.ts` (165 lines)
    45→- `src/app/api/returned-stitched/route.ts` (185 lines — the "broken" old route)
    46→- `prisma/schema.prisma` lines 846-893 (`ReturnedStitchedInventory` model — has `inventoryTxnId String?` field)
    47→
    48→**Findings:**
    49→
    50→### Damaged path (`condition='damaged'`)
    51→The route (lines 57-109) calls `recordStockLoss({ createInventoryTransaction: false })` — which creates ONLY a `StockLossRecord`. No `InventoryTransaction` is created (by design — damaged items aren't added to stock). **No `ReturnedStitchedInventory` row is created either.**
    52→
    53→### Non-damaged path (`condition='perfect' | 'good' | 'open_box'`)
    54→The route (lines 111-160) calls `processInventoryTransaction({ transactionType: 'return_stitched_received' })` — which creates an `InventoryTransaction` row AND updates `InventoryPool` (increments onHand, recalculates WAC, flips trackInventory for MTO variants). **But no `ReturnedStitchedInventory` row is created.** The `txnResult.transactionId` is returned to the client but never persisted as `ReturnedStitchedInventory.inventoryTxnId` (because no such row exists).
    55→
    56→### Verdict — PROD-002 claim is HALF-TRUE
    57→
    58→| Claim | Reality |
    59→|---|---|
    60→| "Creates an InventoryTransaction" | ✅ TRUE (for non-damaged path only) |
    61→| "Creates a ReturnedStitchedInventory row" | ❌ FALSE — neither path creates one |
    62→| "Establishes a valid inventoryTxnId link" | ❌ FALSE — there's no register row to link FROM |
    63→| "Equivalent to POST /api/returned-stitched" | ❌ FALSE — the old route creates the register but not the txn; the new route creates the txn but not the register. They are complementary, not equivalent. |

   203→```
   204→StockLossRecord cmrzhn46s000nmmjz8a10x808
