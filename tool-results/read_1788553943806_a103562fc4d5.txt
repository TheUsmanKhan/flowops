   548→/// Item Exchange System — tracks a single item exchange request.
   549→/// An exchange can only be created against an order_item belonging to a
   550→/// DELIVERED order. Two exchange methods with distinct sequencing:
   551→///   - courier_replacement: new item dispatched first, courier collects old
   552→///   - customer_self_return: customer ships old item back FIRST, it's
   553→///     manually verified, THEN the new item is dispatched
   554→///
   555→/// newOrderId/newOrderItemId are nullable — populated only once the linked
   556→/// exchange order (order_source='exchange') is created, which for
   557→/// customer_self_return happens LATE (after old item verification).
   558→///
   559→/// priceDifference is GENERATED as newItemPrice - oldItemPrice. If positive,
   560→/// customer owes; if negative, refund due.
   561→///
   562→/// "Customer did not return" is a supported terminal outcome — the value of
   563→/// the never-returned old item becomes a recoverable amount, and Step 2's
   564→/// server actions will call the existing flagCustomer() with reason
   565→/// "Exchange item not returned".
   566→///
   567→/// NOTE: Managed jointly by Prisma (ORM access) + raw SQL (migration 003).
   568→/// Do NOT run `prisma db push` — it would drop the GENERATED column, CHECK
   569→/// constraints, and RLS policies Prisma can't represent. Use `prisma
   570→/// generate` only; schema changes go through /supabase/migrations/*.sql.
