   261→PART 2: HELPER FUNCTIONS & TRIGGERS
   262→━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   263→
   264→Create the following PostgreSQL functions:
   265→
   266→1. get_active_company_id() RETURNS UUID
   267→   Reads user_settings.active_company_id for the current auth.uid().
   268→   Used in ALL RLS policies. Must be SECURITY DEFINER, STABLE.
   269→
   270→2. get_active_org_id() RETURNS UUID
   271→   Reads user_settings.active_org_id for the current auth.uid().
   272→
   273→3. is_elevated_employee(p_company_id UUID) RETURNS BOOLEAN
   274→   Checks if current user's employee record for p_company_id has a role
   275→   with role_tier = 'elevated'. Used in admin-only RLS policies.
   276→
   277→4. has_permission(p_company_id UUID, p_permission_key TEXT) RETURNS BOOLEAN
   278→   Checks role_permissions for current user's role in p_company_id.
   279→   If the user's role_tier = 'elevated', return TRUE immediately (bypass).
   280→   Otherwise check role_permissions table.
   281→
   282→5. handle_new_user() — TRIGGER FUNCTION
   283→   After INSERT on auth.users:
   284→   - Creates profiles row
   285→   - Creates user_settings row
   286→   - Marks is_onboarded = FALSE
   287→
   288→6. update_updated_at() — TRIGGER FUNCTION
   289→   Updates the updated_at column to NOW() before any UPDATE.
   290→   Apply this trigger to: profiles, organizations, companies, employees,
   291→   roles, user_settings.

   294→PART 3: ROW LEVEL SECURITY (RLS) POLICIES
   295→━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   296→
   297→Enable RLS on ALL tables. Write explicit policies for each.
   298→
   299→profiles:
   300→  SELECT: auth.uid() = id
   301→  UPDATE: auth.uid() = id
   302→
   303→organizations:
   304→  SELECT: owner_id = auth.uid()
   305→          OR EXISTS (SELECT 1 FROM employees e 
   306→                     JOIN companies c ON c.id = e.company_id 
   307→                     WHERE c.organization_id = organizations.id 
   308→                     AND e.user_id = auth.uid() 
   309→                     AND e.status = 'active')
   310→  INSERT: auth.uid() IS NOT NULL (any logged in user can create an org)
   311→  UPDATE: owner_id = auth.uid()
   312→  DELETE: owner_id = auth.uid()
   313→
   314→companies:
   315→  SELECT: company_id = get_active_company_id()
   316→          AND EXISTS (SELECT 1 FROM employees 
   317→                      WHERE company_id = companies.id 
   318→                      AND user_id = auth.uid() 
   319→                      AND status = 'active')
   320→  INSERT: organization owner can create companies
   321→  UPDATE: is_elevated_employee(id) = TRUE
   322→  DELETE: DISABLED (use is_active = FALSE instead)
   323→
   324→employees:
   325→  SELECT: company_id = get_active_company_id()
   326→          AND company_id IN (SELECT company_id FROM employees 
   327→                              WHERE user_id = auth.uid() 
   328→                              AND status = 'active')
   329→  INSERT: has_permission(company_id, 'employees.invite') = TRUE
   330→  UPDATE: is_elevated_employee(company_id) = TRUE
   331→          OR (auth.uid() = user_id AND -- employee can update own limited fields
   332→              -- Only allow updating: avatar, phone on own profile)
   333→  DELETE: DISABLED (use status = 'terminated' instead)
   334→
   335→roles:
   336→  SELECT: company_id = get_active_company_id()
   337→  INSERT: has_permission(company_id, 'settings.roles.manage') = TRUE
   338→  UPDATE: has_permission(company_id, 'settings.roles.manage') = TRUE
   339→          AND is_system_role = FALSE
   340→  DELETE: has_permission(company_id, 'settings.roles.manage') = TRUE
   341→          AND is_system_role = FALSE
   342→
   343→role_permissions:
   344→  SELECT: company_id = get_active_company_id()
   345→  INSERT: is_elevated_employee(company_id) = TRUE
   346→  DELETE: is_elevated_employee(company_id) = TRUE
   347→
   348→invitations:
   349→  SELECT: invited_by = auth.uid()
   350→          OR invited_email = (SELECT email FROM profiles WHERE id = auth.uid())
   351→  INSERT: has_permission(company_id, 'employees.invite') = TRUE
   352→  UPDATE: token IS NOT NULL (accepting via token — public but token-gated)
   353→
   354→user_settings:
   355→  SELECT: user_id = auth.uid()
   356→  INSERT: user_id = auth.uid()
   357→  UPDATE: user_id = auth.uid()
   358→
   359→audit_logs:
   360→  SELECT: company_id = get_active_company_id()
   361→          AND is_elevated_employee(company_id) = TRUE
   362→  INSERT: auth.uid() IS NOT NULL
   363→  UPDATE: DISABLED (immutable — no updates ever)
   364→  DELETE: DISABLED (immutable — no deletes ever)
   365→
   366→metric_events:
   367→  SELECT: company_id = get_active_company_id()
   368→  INSERT: auth.uid() IS NOT NULL
   369→  UPDATE: DISABLED
   370→  DELETE: DISABLED

   494→PART 5: AUTHENTICATION FLOWS
   495→━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   496→
   497→Implement all 6 flows using Supabase Auth + Next.js Server Actions:
   498→
   499→─────────────────────────────
   500→FLOW 1: REGISTRATION
   501→─────────────────────────────
   502→Form fields: full_name, email, password, confirm_password
   503→Zod validation: min 8 chars password, email format, passwords match
   504→Server Action:
   505→  1. supabase.auth.signUp({ email, password, options: { data: { full_name } } })
   506→  2. Supabase trigger auto-creates profiles + user_settings rows
   507→  3. Return success → redirect to /onboarding
   508→  4. Insert audit_log: action "auth.registered"
   509→
   510→─────────────────────────────
   511→FLOW 2: LOGIN
   512→─────────────────────────────
   513→Form fields: email, password
   514→Server Action:
   515→  1. supabase.auth.signInWithPassword({ email, password })
   516→  2. Check if profiles.is_onboarded = TRUE
   517→  3. Check if user has pending invitations for their email
   518→  4. If is_onboarded = FALSE → redirect to /onboarding (pass pending invites)
   519→  5. If is_onboarded = TRUE → check user_settings.active_company_id
   520→  6. If active_company_id is NULL → redirect to /onboarding
   521→  7. Else → redirect to /dashboard
   522→  8. Insert audit_log: action "auth.login"
   523→
   524→─────────────────────────────
   525→FLOW 3: LOGOUT
   526→─────────────────────────────
   527→Server Action:
   528→  1. supabase.auth.signOut()
   529→  2. Clear Zustand workspace store
   530→  3. Redirect to /login
   531→  4. Insert audit_log before sign out: action "auth.logout"
   532→
   533→─────────────────────────────
   534→FLOW 4: FORGOT PASSWORD (OTP Code Flow)
   535→─────────────────────────────
   536→This is a 3-step flow:
   537→
   538→STEP 1 — /forgot-password
   539→  Form: email input
   540→  Server Action:
   541→    supabase.auth.resetPasswordForEmail(email, {
   542→      redirectTo: process.env.NEXT_PUBLIC_APP_URL + '/reset-password'
   543→    })
   544→  UI: Show "Check your email. We sent a 6-digit code." message.
   545→  Note: Supabase sends an email with a magic link that contains a token.
   546→
   547→STEP 2 — /reset-password (user arrives via email link)
   548→  The email link brings user to /reset-password?token_hash=xxx&type=recovery
   549→  Server Action in route:
   550→    1. Exchange token hash for session:
   551→       supabase.auth.verifyOtp({ token_hash, type: 'recovery' })
   552→    2. On success: show "Create New Password" form
   553→
   554→STEP 3 — New Password Form
   555→  Form fields: new_password, confirm_password
   556→  Zod validation: min 8 chars, passwords must match
   557→  Server Action:
   558→    1. supabase.auth.updateUser({ password: new_password })
   559→    2. Sign out all other sessions for security
   560→    3. Redirect to /login with success toast
   561→    4. Insert audit_log: action "auth.password_reset"
   562→
   563→─────────────────────────────
   564→FLOW 5: SESSION MANAGEMENT (Middleware)
   565→─────────────────────────────
   566→In middleware.ts:
   567→  1. Refresh Supabase session on every request (prevent token expiry)
   568→  2. If no session → redirect to /login (except for auth routes)
   569→  3. If session exists + is_onboarded = FALSE → redirect to /onboarding
   570→  4. Protect all /dashboard/* and /employees/* and /roles/* routes
   571→  5. Allow /login, /register, /forgot-password, /reset-password without auth

   731→PART 11: CRITICAL RULES — DO NOT VIOLATE
   732→━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   733→
   734→1. NEVER use "any" TypeScript type. Use generated Supabase types everywhere.
   735→
   736→2. NEVER expose service_role key on client side. 
   737→   Server Supabase client is only used in Server Actions and middleware.
   738→
   739→3. NEVER write WHERE company_id = X filters in Next.js code.
   740→   RLS handles all data isolation. Trust the database.
   741→
   742→4. NEVER delete employees records. Set status = 'terminated' only.
   743→
   744→5. NEVER delete audit_logs or metric_events rows. These are immutable.
   745→
   746→6. NEVER hardcode permission strings in components.
   747→   Always import from /lib/constants/permissions.ts
   748→
   749→7. EVERY Server Action must:
   750→   a. Validate input with Zod before any database operation
   751→   b. Use the server Supabase client (never browser client)
   752→   c. Return typed { success: boolean, data?: T, error?: string }
   753→   d. Call insertAuditLog at the end on success
   754→
   755→8. All company-scoped data tables that will be built in future modules 
   756→   (orders, products, inventory, shipments, returns) MUST include:
   757→   - company_id UUID NOT NULL
   758→   - created_by_employee_id UUID REFERENCES employees(id)
   759→   - created_at TIMESTAMPTZ DEFAULT NOW()
   760→   - updated_at TIMESTAMPTZ DEFAULT NOW()
   761→   This ensures KPI system can always track who did what.

   764→   verifyOtp method — NOT a custom code system.
